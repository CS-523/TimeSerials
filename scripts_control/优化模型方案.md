# 优化模型方案：输入一段 x，优化未来 x3/x4/x6/x8 使 y4 最大

> 对应 README 任务 4："输入一段时间数据，优化未来一段时间的 x3、x4、x6、x8；使 y4 或者 y 最大。"
> 本文档确定：**目标 = 仅最大化 y4**（不含标量 Y / YHead）。

---

## 1. 模型组成

方案复用 `src_control/` 里两个**已训好、可微**的预测模型，冻结后串联：

| 模型 | 类 / checkpoint | 作用 |
|---|---|---|
| x 预测器（默认轨迹） | `SS_NN_Hybrid(dim_u=8,dim_y=8)` / `checkpoints/x_forecast_best.pt` | `forecast(ctx,H)` → 未来 x1–x8（真自回归） |
| y4 预测器（奖励） | `SS_NN_Hybrid(dim_u=8,dim_y=4)` / `checkpoints/ss_nn_best.pt` 的 `model` 键 | `forward(u)` → y1–y4，`y4 = u[...,3]` |

两者共用 `data/processed/scalers.npz`（`x_mean`/`x_scale`）的标准化空间，可直接串联。

其中 `SS_NN_Hybrid`（`src_control/models/state_space_nn.py`）= **线性状态空间基线**（`LinearSSTorch`，`A/B/C/D` 用 N4SID 子空间辨识初始化）+ **残差 MLP**（`ResidualMLP`，滑窗前馈），输出 `y = y_lin + y_res`。

---

## 2. 为什么那 4 个变量是"自由"的

**"自由"指"可控（能被操作员主动设定）"，不是"可预测/不可预测"。**

所有 8 个 x 的未来值都可以被 x 预测器预测出来（这是"不干预"的默认轨迹）。但优化只允许在**你实际能动手控制的变量**上做搜索：

- **可控（决策变量）：x3、x4、x6、x8**
  - REPORT 中：x3/x4 是"控制自由度"、x6 是"高位产能/反应浓度"、x8 是可控累计投料。
- **不可控（随预测走，优化时不改动）：x1、x2、x5、x7**
  - 外生/环境变量（如 pH、温度）和累计结果量，操作员不能直接设定。

因此完整闭环：

```
过去窗口 ──x预测器──▶ 未来 x1..x8 默认轨迹
                         │
        非自由维(x1,x2,x5,x7) 固定在预测值（不可控，只能预测）
        自由维  (x3,x4,x6,x8) 当搜索变量（初值=预测值，加训练分布界）
                         │
                    组装完整未来 x ──y4预测器──▶ 最大化未来 y4
```

即：**非自由变量由预测器预测；自由变量在预测值附近做有界搜索。**

## 3. 设计

### 3.1 数据流（每个样本）

```
输入: 过去窗口 x_ctx  (C=32, 标准化)
  │
  ├─ x 预测器.forecast(x_ctx, H=48)         → x_fut_default (H,8)   [默认轨迹]
  │
  ├─ 决策变量 x_ctrl (H,4)  = 取 x_fut_default 的 [x3,x4,x6,x8] 列，
  │      requires_grad=True，初值=预测值(clamp)，
  │      界=训练分布 [1%,99%] 分位数（默认 --bounds-mode train）
  │
  ├─ 每步: 组装 future_x (H,8) = 默认轨迹，用 x_ctrl 覆盖第 2/3/5/7 列
  │        u = cat([x_ctx, future_x], dim=0)  → (C+H, 8)
  │
  └─ y4 预测器.forward(u[None])            → y (1, C+H, 4)
          目标 = max mean( y[0, C:, 3] @观测采样相位 )    # H=48 覆盖一个日采样周期
          loss = -reward + λ·‖x_ctrl − x_default‖²       # λ = --effort-penalty
```

### 3.2 核心机制

1. **决策变量索引**：`DECISION_IDX = (2,3,5,7)`（x3,x4,x6,x8）；`FIXED_IDX = (0,1,4,6)`（x1,x2,x5,x7）。
2. **优化器**：**投影梯度上升**，`torch.optim.Adam` 对 `x_ctrl (H,4)` 做多起点优化（起点 0 = 预测默认值 clamp，其余界内随机），每步 `clamp_` 投影到标准化上下界。
3. **搜索界（默认 = 训练分布）**：默认 `--bounds-mode train`，用训练集（去 padding）x3/x4/x6/x8 的 `[quantile, 1-quantile]` 分位数界（`--bound-quantile 0.01` = 1%-99%）；可选 `--bounds-mode physical` 用宽松物理界（x3∈(0,110)、x4∈(26,36)、x6∈(5000,50000)、x8∈(0,1500)）。
4. **标准化空间一致性**：所有优化在标准化空间进行，界统一换算成标准化界 `lo_norm=(lo_raw−x_mean[c])/x_scale[c]`、`hi_norm=(hi_raw−x_mean[c])/x_scale[c]`；结果再反标准化输出原始值。
5. **reward 对齐采样相位**：y4 是「日采样」目标（约每 48 步 = 24h 测一次）。默认 `--horizon 48` 覆盖一个完整采样周期；reward = 观测相位上的 y4 均值（`y4_phase_mask`，只传相位不传值，采样时刻表已知、采样值未知），无观测点回退末点。避免在「盲区」上求均值导致外推虚高。
6. **控制 effort 正则（可选）**：`loss = -reward + λ·‖x_ctrl − x_default‖²`，惩罚控制量相对默认轨迹的偏离，抑制「瞬时大幅跳变」（物理不可达）与代理模型外推。默认 `λ=0`（关闭），由 `--effort-penalty` 调节。

## 4. 实现

- **核心优化器** — `src_control/optimization/optimizer.py`：`maximize_y4`（优化主循环）、`_assemble_future`（梯度流组装，`torch.cat` 逐列拼接保证梯度只回传 `x_ctrl`）、`standardized_bounds`（物理界→标准化界）。`x_ctrl` 是唯一 `requires_grad=True` 的叶子，两个模型 `eval()` 并冻结参数。
- **CLI 驱动** — `scripts_control/04_optimize.py`：加载两个 checkpoint + `scalers.npz`，`train_distribution_bounds()` 从训练集统计分位数界，取 test 样本 context 调 `maximize_y4`，反标准化 + 画图 + 汇总 `optimize_metrics.json`。
  - 参数：`--context 32 --horizon 48 --n-starts 5 --max-iter 200 --lr 0.05 --bounds-mode train --bound-quantile 0.01 --effort-penalty 0.0`
  - `--all-test`：遍历整个 test 集，汇总 baseline/optimized y4 提升分布。
  - 产物：`results/optimization/optimized_vs_baseline_{i}.png` + `optimize_metrics.json`

## 5. 关键结论

1. 目标稳定上升、无退化（`no-regression` 保证：初值 = 默认轨迹是可行点，梯度上升不应变差）。
2. **对齐采样相位 + 分布内硬约束，把外推虚高从 +84% 收敛到 +32%**（样本 240116，train 1%-99% 界）。
3. **硬约束比 `--effort-penalty` 有效**：effort 0.1→1.0 只把 +32% 压到 +23%，收紧界直接到 +16.6%。
4. **残留「贴边」**：y4 预测器对 x 的响应接近单调，只要界非零宽，最大化 y4 就会贴边；剩下是「真实可实现的提升」还是「模型在分布边缘的偏差」，需留出集 counterfactual 验证。
5. 默认 `--bounds-mode train --bound-quantile 0.01` 是合理中间选择；更保守可用 `--bound-quantile 0.05`。

## 6. 验证（端到端）

1. **冒烟**：`python -m scripts_control.04_optimize --n-samples 1 --plot-max 1`，确认两个模型加载成功、优化不报错、输出 PNG + JSON。
2. **目标上升**：对每个测试样本，`optimized_y4_mean ≥ baseline_y4_mean`（初值本身是可行点，梯度上升不应变差；若变差说明投影/标准化 bug）。
3. **边界**：断言优化后的 x3/x4/x6/x8 反标准化后落在搜索界内。
4. **可视化核对**：PNG 里优化轨迹与默认轨迹合理，y4 曲线提升、只在观测点标点。
5. **批量评估**：`python -m scripts_control.04_optimize --all-test`，看 y4 提升分布；调 `--bounds-mode physical` 对照确认外推虚高、调 `--effort-penalty` 观察控制轨迹更平滑。
